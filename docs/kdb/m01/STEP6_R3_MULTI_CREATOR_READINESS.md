# Step 6 R3 multi-creator ACL boundary — local only

`VERIFIED_LOCAL_SCOPED` applies only to two explicitly configured direct-login fixture creators in `tests/kdb/pg17_step6_r3_multi_creator.py`. Each creator's global function default ACL is changed in its own directly authenticated session; the test observes creator identity, global catalog rows, raw and exploded function ACLs, grantor/grantee/grant options and effective EXECUTE. After A's correction, B's default and new function remain PUBLIC executable until B is independently corrected. Both corrected creators' new functions deny PUBLIC, anon, authenticated and service_role while an explicitly named test grantee is allowed. Pre-existing functions and CREATE OR REPLACE retain their pre-existing PUBLIC EXECUTE.

`EXPOSED_OUTSIDE_CREATOR / OTHER_CREATORS_UNCONTROLLED`: a third independent creator with schema CREATE and unchanged defaults creates a PUBLIC-executable function. Schema USAGE may mask invocation without removing function EXECUTE; a negative schema-permission test and a temporary schema-USAGE test demonstrate the difference. SET ROLE cases are local simulations, not direct-login authentication evidence. The same applies to the named NOLOGIN grantee call. This does not prove that all existing or privileged creators are controlled.

Cleanup checks the named fixture roles, schema, functions, default ACLs and memberships; compares KDB runtime role/membership and KDB schema/table ACL preimages. `ZERO_RESIDUAL_BOUNDED` is not full catalog or hosted raw-ACL restoration. No accepted SQL001–003, P25/P26, prior test or hosted grant is changed. `OWNER_TRANSFER_MEMBERSHIP_RISK / RAW_NULL_ACL_POSTCOMMIT_RECOVERY_UNPROVEN / REAL_HUMAN_AUTHORITY_UNPROVEN / HOSTED_VERIFIED_NO / NOT_ADMITTED / NOT_SECURITY_PASS` remain open.
